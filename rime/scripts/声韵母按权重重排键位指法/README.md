# 声韵母按权重重排键位指法

围绕 yoyo 音形方案的**两码简码位**做布局优化与字典改写的一组脚本。

> **在本仓库中运行的注意事项**：仓库里的 `rime/yoyo-yx-word.dict.yaml` 是剔除了零权重长尾的**发布版**（60.0 万词）。这组脚本会原地改写它。若你要重排码位，应当先用完整词库（149.1 万词）替换该文件，跑完流程后再用 `rime/scripts/trim_word_dict.py` 重新生成发布版。直接在发布版上重排不会出错，但腾出的码位会由更少的候选来补，结果与完整版不同。
>
> 另外 `remap_codes.py` **只能跑一次**，重复执行会二次置换编码。

解决的问题：两码简码是最省力的输入位置，数量有限（15 声母键 × 12 指法 = 180 个码元，× 4 条单手输入路径 = 720 个槽位），需要按字词权重把最高频的字词放进最容易敲的槽，把被挤出的条目按码长逐级顺延，并把腾空的位置重新补满——全程保持字典自洽。

## 码位模型

这是全套脚本的共同基础，定义在 `dict_model.py`。**码长只数字母**，`_ + ! @ - < >` 不计入。

模型里有两个**正交**维度，分清它们是理解全套脚本的前提。

### 维度一：前缀 = 输入路径（全局 4 条）

按 schema 的 `八荒六合` 算法：

```
单手不带空格：_左  +右
单手带空格：  <左  >右
```

所以 `_dA` 与 `+dA` 是**同一码元的左手版与右手版**（布局镜像对称，两只手都能打出全部 180 个码元），`<dA` 与 `>dA` 同理。四者是四条独立的输入路径，都是一简、都是两键，且**与条目是字还是词无关**——故 `PREFIXES = ("_", "+", "<", ">")` 是模块级全局常量。

**推论一**：同槽四个前缀的击键成本对等，把高权重放 `_`/`<` 只是一个便于校验的约定，不是性能优化。`order_slot()` 维持这个约定，纯粹为了次序可预期。

**推论二**：`yoyo-yx.dict.yaml` 把 char 与 word 两个文件 `import_tables` 成**同一部词典**，所以两码槽位空间是全局的——共 15 键 × 12 指 × 4 前缀 = **720 槽**，跨文件必须唯一，否则一简出现重码就无法唯一顶屏（`auto_select_pattern`）。当前占用 700/720，空缺的 20 个来自 5 个无候选码元 × 4 前缀。

### 维度二：码长分层 = 条目类型

| 条目类型 | 落地文件 | 2 码 | 4 码 | 8 码 | 全码 |
|----------|----------|------|------|------|------|
| 单字 | `yoyo-yx-char.dict.yaml` | 前缀 + `XX` | `!XXXX@` | — | `!XXXX@-XX`（6） |
| 多字 | `yoyo-yx-word.dict.yaml` | 前缀 + `XX` | `XXXX` | `XXXXXXXX` | 12 位裸码 |

分层只由**文本长度**决定，因此条目该写进哪个文件也只由文本长度决定（`codec_for(text)`），**与它占用哪个前缀无关**。`Codec.default_prefixes` 仅是该类条目在非 A 槽的默认策略（字表用 `_+`、词表用 `<>`），A 槽的前缀由 A 位方案显式指定，不受它约束。

### 顺延与补位

```
字：2（_/+）→ 4（!XXXX@）→ 6（!XXXX@-XX）
词：2（<>） → 4 → 8 → 12
```

四码/八码一律由该条目的**全码截取前 4/8 位**得到，不重新推导。

降级（顺延）和升级（补位）在两个字典里是同一套算法，只有层级表和码型不同，因此由 `Codec` 参数化，统一实现一份：

| 函数 | 作用 |
|------|------|
| `demote(store, codec, text, level)` | 把 text 从 level 挤到下一层，目标层占用者递归下挤 |
| `promote(store, codec, letters, level, prefix)` | 补 level 层空位，从下一层按权重上提，递归补它腾出的坑 |
| `place_short(...)` | 把字/词挂到指定两码位（现有两码改挂，或从更长码提上来） |
| `order_slot(...)` | 按约定排定同槽前缀次序 |

**边界规则**：全码条目恒存在，降级到全码时只并入权重不新建；从全码上提时保留条目、只移交权重（置 0）。低于全码的层级则是真正的移动。

**多音字**：一个字可在不同读音（不同两码前缀）下各持一套码，如 `得` 同时有 `_dF` 和 `!dLqE@`。因此升级资格按读音（两码前缀）分别判定。词无此情况，以整词为范围——由 `Codec.multi_reading` 区分。

## 脚本详解

### ① `optimize_shengyun_layout.py` — 布局优化

穷举搜索声母键位与韵母指法的最优排布，使加权击键代价最低。**只产报告，不改字典。**

**模型**

- 声母分 15 组映射到 `qwertasdfgzxcvb`（`INITIAL_GROUPS`），如 `w: (p, sh)`
- 韵母分 12 组映射到 `ABCDEFGHIJKL`（`FINAL_GROUPS`）
- 指法容易度三档（`FINGER_EASE`）：`A` = 1.0，`BCDEF` = 0.5，`GHIJKL` = 0.1
- 组合容易度 = 键位容易度 × 指法容易度，目标最大化 `Σ(权重 × 容易度)`

**输入**

| 参数 | 默认 | 说明 |
|------|------|------|
| `--lexicon` | `data/词库-chai-ordered.txt` | 字词 + 拼音 + 权重（三列制表符分隔） |
| `--dictionary` | `0--core/resource-yoyo音形终版/char.dict.yaml` | 改用已选好两码候选的字典（与 `--lexicon` 互斥） |
| `--key-ease` | `prompts/键位分布目标.txt` | 按键容易度表 |
| `--per-cell` | `2` | 每槽放几个字词 |
| `--min-code-ease` | `gA=1.5` | 保护约束，可重复传 `编码=最低容易度` |
| `--unconstrained` | — | 关闭全部最低容易度保护 |

**输出**

| 参数 | 默认 | 内容 |
|------|------|------|
| `--output` | `prompts/声韵母最省力排布结果.md` | A 位分配、权重前 105 未进 A 的字词、全部两码记录 |
| `--details-output` | — | 全部两码字词的新旧编码明细 |

`词库-chai-ordered.txt` 格式：

```
的	de5	92123018
可以	ke3 yi3	20283603
```

### ② `remap_codes.py` — 旧码→新码置换

换键位布局后，把字典里所有编码的字母整体替换。

`LOWER`（15 声母键）与 `UPPER`（12 指法）各是一个**置换**，合成一张 `str.maketrans` 表对码串一次性 translate，避免逐条替换的链式覆盖（如 `a→d` 后 `d→a` 又换回去）。启动时校验两表都是双射，否则退出。非字母字符原样保留。

```bash
python3 remap_codes.py [--dict char|word|all]
```

```
yoyo-yx-word.dict.yaml: 数据行 2761071, 码变更 2761012
```

### ③ `assign_a_codes.py` — A 位就位 + 顺延

A 位 = 15 个二字母码（`qA`…`bA`）× 4 条输入路径 = **60 个槽位**，全部手工指定。

`A_SLOTS` 是 A 位的**完整真相**——每槽放什么、放不放，只在这里定义：

```python
A_SLOTS = {
    "qA": {"_": "吃", "+": "没有", "<": "美国", ">": "模型"},
    "bA": {"_": "而且", "+": "所以", "<": "而", ">": "安全"},  # 字词可任意混放
    ...
}
```

- **值可以是字也可以是词**，与前缀无关。条目走哪套顺延分层、写进哪个文件由 `codec_for()` 按文本长度决定，故 `_bA` 这行可能出现在词表文件里、`<bA` 可能出现在字表文件里——对 Rime 无差别，两文件同属一部词典。
- **省略某前缀＝该槽留空**，原占用者顺延下去。
- 同一文本不得占用两个槽位（`check_plan()` 拦截）。
- 因为槽位归属跨两个文件，本脚本**必须同时读写字表与词表**，没有 `--dict` 开关。

**执行顺序**

```
check_plan()   校验码位合法、前缀合法、无重复文本
两阶段 apply_plan():
  ① 逐槽腾空——清走 60 个槽上所有不属于方案的条目
  ② 逐槽落位——place_short() 把方案文本挂上去
verify()       跨两表逐槽比对：占用唯一、文本正确、文件正确，不符即 SystemExit
save()         两表一起写盘
```

先整体腾空再整体落位，是为了避免落位过程误伤「当前在别的 A 槽、但仍待安排」的条目。

**腾空的两种走法**：占用者在本文件里有全码 → `demote()` 顺延；否则（或它还留着别的一简）→ 直接撤这一行。后者对应历史遗留的孤立简码行，例如 `没有 +qA` 曾写在字表文件里而其码链在词表，撤掉不丢任何东西。

**A 槽不跑 `order_slot()`**：表里写的顺序就是最终顺序，脚本不再按权重重排。

**关键细节**：`demote()` 里目标层的占用者递归下挤，权重高者最终保住较短码。例 `方`(2,500,808) 与 `放`(2,388,398) 争 `!tAtA@`，`方` 拿四码、`放` 退到 `!tAtA@-tH`。

```bash
python3 assign_a_codes.py
```

### ④ `fill_vacant_codes.py` — 补足空位

字词迁入 A 位后原来的两码位会空出来（`的` 从 `_dF` 走了），此脚本从更长码位按权重把最合适的条目提上来。

**只管非 A 槽**。A 槽（`qA`…`bA`）已由 `A_SLOTS` 完整指定，包括故意留空的位，此处一概跳过。这同时保证了跨文件不撞车：非 A 槽里字表只用 `_+`、词表只用 `<>`，两文件的槽位空间天然不相交，各自独立处理即可。

**目标数**：每槽在本文件的两个默认前缀上各挂一条（`len(codec.default_prefixes)`）。

**流程**：先把已有条目挪到靠前前缀（空位集中到尾部）→ 逐个空位 `promote()` → `order_slot()` 排定次序。

某槽在字典里没有任何候选时保持空缺并汇总报告，不视为错误：

```
字表：变更 5 处，共 13484 条目
  字 eB 前缀次序按权重调整
  仍空缺（无候选）: sE×2 fB×2 fJ×2 fL×2 xE×2
```

```bash
python3 fill_vacant_codes.py [--dict char|word|all]
```

## 标准执行顺序

```bash
cd 0--core/scripts/声韵母按权重重排键位指法

python3 optimize_shengyun_layout.py     # ① 重新优化布局时才跑
python3 remap_codes.py     --dict all   # ② 键位布局变更时跑一次
python3 assign_a_codes.py               # ③ A 位就位 + 顺延（必然两表同改）
python3 fill_vacant_codes.py --dict all # ④ 补足空位
```

- ② **只能跑一次**，重复执行会二次置换。
- ③④ **幂等**，可反复执行（已验证：连跑两轮字典 md5 不变）。
- 改动前建议先 commit。词表 276 万行，出错时 `git checkout HEAD -- yoyo-yx-word.dict.yaml` 恢复最快。

耗时参考：③ 约 8 秒，④ 约 33 秒。

## 设计约定

**单一真相源**。每个事实只在一处定义：

| 事实 | 定义处 |
|------|--------|
| 四条输入路径 | `dict_model.PREFIXES` |
| 码位分层与码型、条目落哪个文件 | `dict_model.CHAR` / `WORD` / `codec_for()` |
| A 位 60 个槽放什么 | `assign_a_codes.A_SLOTS` |
| 非 A 槽用哪两个前缀 | `Codec.default_prefixes` |

**前缀与分层解耦**。前缀属于槽位（输入动作），分层属于条目（文本长度）。两者曾因「字表只放字、词表只放词」而偶然重合，一旦要混放就必须拆开——否则无法表达「词占 `_XX`」这类需求。

**没有硬编码的空位表**。哪些槽填不满由「有无候选」决定，不靠人工维护清单。

**删除用墓碑标记**。`Store.kill()` 只置 `alive=False`，`compact()` 时才真正剔除，保证输出行序与原文件一致——这样 diff 只反映真实的编码变更。

**校验前置**。`assign_a_codes.verify()` 在写盘前逐槽比对，不符直接退出，不会写出半成品字典。
