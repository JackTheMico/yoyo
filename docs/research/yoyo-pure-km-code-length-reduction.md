# 调研报告：yoyo-pure-km 如何进一步降低码长 / 以更少击键打出更多字

> **状态**：研究完成 (Research Completed) · 2026-09-02
> **问题**：在「物理一击最多 2 个码元、纯形、无空格顶功」的约束下，yoyo-pure-km 还有哪些经过验证的手段能继续降低每字击键数？
> **方法**：以真实字典（`yoyo-pure.dict.yaml` / `yoyo-user.dict.yaml`）+ 音形词频表（`yoyo-yx-word/char.dict.yaml`，仅借「词+权重」当词频）做量化审计，并建立「净码长→击键」模型在**打词优先 + 简码优先的最优分词下界**测算；外部先验比对 `kongmingma` 空明码方案。
> **结论先行**：当前方案在最优分词下已做到 **≈0.762 击/字**（击 = 一次并击）。它已非常接近本架构的物理地板（≈0.65–0.70）。**唯一确定可行、零风险、收益最大的一步是「把 % 空格简词空间从 995 补满到 3720」**，预计把下界降到 **≈0.668 击/字（−12.4%）**。再往下需要新增命名空间（短语前缀，借鉴空明码 `*`/`!`）或引入 grammar 整句分词。

---

## 1. 量化模型与口径

**击键模型**（由 `yoyo-pure-km.schema.yaml` 心法决定，顶功只消除确认键、不改击键数）：

- 一次「击」= 一次并击(chord)。空明拳物理层：双手并击 → 2 个码元 = 1 击；单手一击 → 1 个码元 = 1 击。
- 净码长 `net` = code 去掉 `_`/`+` 后的字母数；击键数 `chord = ceil(net/2)`：
  - 一简 `net1` → 1 击；二简/2 码词 `net2` → 1 击（双手并击）
  - 三码单字 `net3` → 2 击；四码词 `net4` → 2 击
- 因此各 token 的「每字击键成本」：**单字简码 1.0、三码单字 2.0、2 字词 1.0、3 字词 0.67、4 字词 0.5**。

**最优分词下界**：按词频表每个多字串若能在库里命中就用其最佳 token（1 击或 2 击），单字回落到自身最佳码；加权求 `Σ击键 / Σ字符`。这是「理论最优用户」下界，真实用户因生僻词、选重、分词典不当会更高，故以下数字应读作**天花板而非日常值**。

**数据源与复现**：见第 7 节。

## 3. 物理天花板分析

为什么 2 字词是降码长的硬约束：

1. **一次并击最多 2 码元** → 2 字词标准编码 4 码 = 2 击 = **1.0 击/字** 已是该 token 的地板，无法再低（除非给它一个 1 击的简码）。
2. **1 击容量有硬上限**：2 码空间 3,720 + % 空间 3,720 = **最多 ~7,440 个 1 击 token**。而仅「未 1 击的 2 字词」就有 **12.1 万个**（去重），词频占 2 字词总频的 **61.4%（7,650 万次）**。容量远小于需求，只能覆盖头部。
3. **即便全词命中，地板也在 ~0.71**：第 7 节投影显示「所有词频表词都命中 4 码」时 ≈0.709 击/字——因为 2 字词占 72% 文本且地板就是 1 击/字。要低于 0.71，只能把更多 2 字词/短语升级成 1 击（吃 1 击容量）。
4. **单字维度已到顶**：94.5% 单字可 1 击，长尾 5.5% 给简码不经济（需抢满的 2 码空间）。

> 结论：本架构在「最优分词」下的实际可达地板约 **0.65–0.70 击/字**。0.762→0.668 这一步（吃满 % 空间）已几乎触底；再降需新增命名空间或整句智能。

## 5. 各手段详述

### L1 · 补满 % 空格简词空间（最大、零风险）

**机制**：`%XY`（双手+空格）/`%_X`（左+空格）/`%+X`（右+空格）是**独立于 2 码空间的命名空间**，末字符到达即由 `pure_popping` 的 Pattern S 一击上屏，纯字典数据、不改 schema。目前只填了 995（源 `research/km_one_chord_tier1.txt` 仅约 995 个候选词）。

**空间**：理论 3,720（60×60 + 60 + 60，与 `gen_brief_words.build_slots` 同口径），**剩余 2,725**。

**市场**：词频表中「尚未 1 击」的 2 字词去重 12.1 万、词频 7,650 万次（占 2 字词频 61.4%）。把这些高频 2 字词升为 % 简词，每词从 2 击→1 击。

**投影（第 7 节脚本实测）**：按词频降序把未 1 击 2 字词塞进 % 空间，整体每字击键率：

| 补 % 简词数 | 每字击键率 | 较当前节省 |
| :--- | :--- | :--- |
| 0（现状） | 0.762 | — |
| 500 | 0.717 | 5.9% |
| 1,000 | 0.699 | 8.2% |
| 1,500 | 0.687 | 9.8% |
| 2,000 | 0.678 | 11.0% |
| **2,725（补满）** | **0.668** | **12.4%** |

**落地改动（纯数据管线）**：改 `gen_brief_words.py` 的词源——把 `TIER1`（≈995 词）换成 `yoyo-yx-word.dict.yaml` 中「2 字词且未在库 1 击」按词频降序的前 3,720 词，过滤掉已 1 击者，保留手动段与冲突回退逻辑不变。`--write` 后自动重生成 `pure_dict_map.lua` + 反查分片，再部署即可。**零代码改动、零行为回归风险**。

**代价**：需记忆更多 % 词键位；但 `%XY = 字1首根+字2首根` 的助记法已基本够用，且用户可用 `yoyo-km-tui --brief` 自助加个人高频词（已支持）。

### L2 · 短语前缀命名空间（借鉴空明码 `*`/`!`）

空明码用 `*`（宏词/专名，如 `*A`→爱国主义）、`!`（短语，如 `!r`→任何）给 4–8 字长词/短语配 1–2 击短码，是其「码长极短」的主因之一。**yoyo-pure-km 目前没有此机制**。

**做法**：选一个当前未占用的 chord 前缀（如某符号键或组合）作为「短语引导符」，配合 `pure_popping` 新 Pattern + `speller.alphabet` 扩展，给超高频 4–8 字短语分配 1–2 击码。可直接复用 L1 剩下（若 L1 未吃满）或另开命名空间。

**收益**：短语密集文本（公文、固定搭配）再降一截，整体或逼近 0.62–0.65。

**风险**：① 占用新 chord，须避让反查（`` ` ``）、标点、次选（`'`）；② 短语码无自然助记，靠肌肉记忆；③ 与「零重码确定性」理念需权衡（短语重码可接受，因有上下文）。**建议先做 L1、确认 % 空间吃满后再评估是否值得新开命名空间**。

### L3 · grammar 整句分词 + 用户词自适应

Rime 标准 `script_translator` + `grammar` 可做整句智能分词与用户自造词。对 yoyo-pure-km 的价值在于：① 减少「字典没词→拆单字 2 击」的回落；② 用户常打的新词自动进个人词库，下次成单 token。

**风险**：会与现有 `table_translator` + `pure_popping` FSM 的「零重码确定性」并存架构冲突，需谨慎设计（如仅在 FSM 未命中时走 script_translator 兜底）。**属 P2 探索项，不建议为降码长而牺牲确定性卖点**。

### L4 · 动态调频 / 主单主词自动

`word_priority` 开关已存在（Ctrl+Shift+C 切主单/主词）。进一步优化是「按上下文自动」而非手动，但收益边际，且会牺牲确定性。低优先级。

### L5 · 标点并击补齐

`km_punct.lua` 已有 16 组双手并击标点。补齐常用标点（句号/逗号/问号/感叹号/书名号/括号）的双手并击，使「打字+打标点」全程不离主键区、0 空格。虽不直接降「字」码长，但属「同样内容更少键」范畴，且用户体验收益大。中优先级、复用现有框架。

### L6 · 物理层改布局 —— 不采纳

一次并击最多 2 码元由 QWERTY 双手结构决定；增码元需换布局或三区并击，代价远大于收益，且破坏与空明码手感共用。**不在考量范围**。

## 6. 推荐落地路线

1. **P0（立即、零风险）**：改 `gen_brief_words.py` 词源为 `yoyo-yx-word` 频排的「未 1 击 2 字词」，把 % 简词从 995 补到 3,720。预期 0.762→0.668（−12.4%）。
2. **P1（短–中期）**：① 标点并击补齐（L5）；② 评估是否新开「短语前缀命名空间」（L2），优先给 top 高频 4–8 字短语 1–2 击。
3. **P2（探索）**：grammar/自适应词（L3）、主单主词自动（L4）——仅在确需突破 0.65 地板且可接受确定性妥协时做。

> 物理现实：本架构在最优分词下可达地板约 **0.65–0.70 击/字**。L1 即吃掉大部分剩余红利；L2 是突破地板的唯一结构性手段。

- 所有数字为「最优分词下界」，非真实用户日常值。
