# 反查里为什么不显示空格并击简词（`%` 版）——根因与修复

> 现象：`rime/yoyo-user.dict.yaml` 里的空格并击简词（`%XY` / `%_X` / `%+X`，共 996 条）
> 在反查里**没有任何呈现**——输入 `` `zhezhong `` 只看到 `vpxb`，看不到 `%_v`。
>
> 根因：**不是代码问题，是数据陈旧**。`rime/lua/yoyo/data/reverse_*.lua` 是 tracked 的生成物，
> 2026-09-07 那次提交用**旧版生成器**重跑了一遍，把 `brief`（第 4 元素）整批抹掉，此后无人察觉。
> 生成器逻辑、`reverse_lookup.lua` 渲染逻辑都是对的，直接把分片重跑一遍即恢复。
>
> 修复：重跑 `generate_reverse_data.py`（23 个分片），并补一条 `--check` 陈旧守卫防止再次静默脱钩。

## 一、事实链（全部可复现）

### 1. 设计上本该显示 `全码 | 简码`

`reverse_lookup.lua:94-106` 的 `make_comment`：词的注释取分片第 2 元素（全码），
若第 4 元素（简码）非空且不等于全码，拼成 `全码 | 简码`。
数据侧由 `generate_reverse_data.py` 的 `load_word_codes`（产 `full_map` 与 `brief_map`）、
`build_candidates`（挂第 4 元素）、`_fmt_cand`（渲染）三处配合。

这套设计在 `research/reverse_brief_words.md` 里已有完整调研与决策记录，
注明「实施状态（2026-08-31）已落地」，并明确修正了「`艾灸` 只显示 `%pL` 而丢全码 `plLO`」的老毛病。

### 2. 仓库里落盘的分片，`brief` 字段数量 = 0

```bash
grep -o '{"[^"]*","[^"]*",[0-9.]*,"[^"]*"}' rime/lua/yoyo/data/reverse_*.lua | wc -l
# 0
```

996 条简词在分片里只有两种形态：

- 有全码的（如 `{"这种","vpxb",273350.0}`）→ 注释只剩 `vpxb`，简码消失；
- 只有简码的（如 `{"艾灸","%pL",629.0}`）→ 恰好因为主码回退才露出 `%pL`，
  但全码 `plLO` 反而丢了（正是 `research/reverse_brief_words.md` 记录过的旧 bug 症状）。

### 3. 生成器本身没坏

`python3 generate_reverse_data.py --dry-run` 报告 `简码(反查展示): 996 条`；
真正写盘后统计 `带简码候选 951 条`。差额 45 条**不是遗漏**——它们是「只有简码、无全码」的词
（如 `我知道 %tD`），`build_candidates` 里 `b == code` 时清空第 4 元素，
避免注释出现 `%tD | %tD`。即 996 条全部有呈现，只是 45 条直接以简码作主码显示。

### 4. 回归发生在哪一次提交

```bash
git log -1 --format='%h %ad %s' --date=iso -- rime/lua/yoyo/data/reverse_z.lua
# 07cce76 2026-09-07 放弃成此方案的说明
git show 07cce76 -- rime/lua/yoyo/data/reverse_z.lua | grep "这种"
# -  ["zhezhong"] = {{"这种","vpxb",273350.0,"%_v"}, ...}
# +  ["zhezhong"] = {{"这种","vpxb",273350.0}, ...}
```

该提交同时把 8 条普通词与 `另外` 写进了用户词表、并重跑了反查生成器，
但用的显然是一份**早于 `7a797c4`（「反查同时显示全码与简码」）的脚本副本**——
结果是把刚上线 6 天的功能按文件粒度整批回退。生成物是 tracked 的，
这种回退在 review 时表现为 23 个分片的大段 diff，很容易被当成「常规重新生成」跳过。

## 二、修复

1. 重跑生成器（`rime/lua/yoyo/data/reverse_*.lua`，23 分片，+951 处第 4 元素）。
2. 生成器加 `--check`：把内存渲染结果与磁盘分片逐字节对比，缺文件 / 内容不一致 / 多余文件
   都报 `[FAIL]` 并退出码 1。写盘与校验共用 `render_all_shards`，避免两条路径漂移。
3. `rime/scripts/readme.md` 补 `brief` 字段约定、`--check` 用法与这次事故的记录。

## 四、部署

反查数据是纯 Lua，**不经过 table.bin 编译**，改完只需把 `lua/` 同步到 Rime 用户目录：

```bash
rsync -a --ignore-times rime/lua/ ~/.local/share/fcitx5/rime/lua/
fcitx5-remote -r     # 或托盘「重新部署」
```

不需要重编词典，也不需要改 schema。

## 五、遗留

- `%` 前缀在候选注释里是裸标记，方案文档（`yoyo-user.dict.yaml` 头部注释）里有
  `%XY`/`%_X`/`%+X` 的释义，但反查注释里没有。若觉得 `%_v` 不够直观，
  可在 `make_comment` 里换成「空格+v」之类，属呈现口味问题，本次未动。
- 陈旧守卫是手动触发的。仓库没有 CI，`--check` 只有在人记得跑的时候才有用；
  真要硬化，得挂到部署脚本第 3 步之前。
