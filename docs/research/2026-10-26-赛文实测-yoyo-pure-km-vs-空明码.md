# 打字性能对比：yoyo-pure-km vs 空明码（kongmingma）

- 赛文：`/home/jackwy/文档/打字练习素材/异地相处的情感感悟.txt`
- 长度：总字符 534｜汉字 473｜标点 61
- 口径：1 击 = 2 个码字符；击数 = ceil(码字符/2)；重码非首选 +1 击；标点两者皆 1 击直出（不计入）

## 结论先说

1. **纯形的编码本身不输空明码。** 把词库变量隔离（只允许两库共有的词条参与切分，各自算自己的码），
   yoyo-pure-km 0.873 击/字，空明码 0.899 击/字——**纯形反而省 3%**。
2. **空明码的胜势全部来自 305 万词库。** 放开词库后空明码 0.795 击/字，比纯形 0.873 省 9%，
   省下的部分来自库里那些「4 码字符就覆盖三四个字」的长词短语（如 `是情感`、`的温柔`、`通过屏幕`）。
3. **把词长锁到 ≤2（贴近真实打词习惯）后，两者基本打平**：0.909 vs 0.913。
   也就是说空明码的相对优势不是「一击两个字」的编码设计，而是「词库里恰好有那条长词」。
4. **纯形的确定性明显更好。** 本篇 473 字里，纯形只有 10.1% 的字需要选重，空明码 22.8%（2.3 倍）。
   不计选重惩罚时两边是 0.818 / 0.719，差距比计入后更大——说明空明码的短码有相当一部分是「多候选短码」。
5. **纯单字打单才是两者的真实分水岭**：纯形 1.332 击/字 vs 空明码 1.216 击/字，纯形多 9.5%。
   这正是 README 里「麓鸣码长最低 1.5、空明能压到 0.7」那段落差的本源——但那是纯打单的极端场景。

一句话：**空明码赢在词库，纯形赢在确定性与不用选重；词库一旦拉齐，纯形的编码效率还略高一点。**

## 七、口径依据（librime 引擎实测）

```
kongmingma chord_composer 探针（真引擎，非推测）：
  单手 'a'  → 码串 a=   （一次击输出 2 个码字符，右手位补 = 占位）
  单手 'y'  → 码串 =t   （右手，左手位补 =）
  双手 'ay' → 码串 at   （一次击，两手各出 1 个）
=> 2 码字符 = 1 击，与纯形「双手并击 = 2 码元 = 1 击」同构。
```

## 八、注意

- 理论最优 ≠ 实战：上面是「每处都选最优切分」的下界。用户 10/25 极速杯实测
  空明码 码长 1.0（491 字 / 503 键）、打词率 80.04%，比本表 0.795 高约 26%，
  差额来自回改、选词犹豫、没用上长词短码。
- 未含标点：61 个标点两方案都是 1 击直出，双方持平，故未计入汉字击数。
- 空明码重码占比可能偏高：DP 偏爱长词，而长词在 305 万库中重码更多；
  真人偏好高频词，实际选重负担应低于 22.8%。
- 击速假设两边相同；真实手感差异（空明声韵单手 vs 纯形字根单手）未建模。
