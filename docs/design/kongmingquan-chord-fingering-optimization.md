## 0. 结论先行

1. **你的直觉命中了一处真问题，但它不是「跨度大」，而是「一根手指按两个键」**：`>` 码元（左 `de` / 右 `ik`）是 44 个双键码元里**唯一**需要单指纵向压条的组合（中指同时压 `e` 与 `d`）。它不属于你给的那张 63 格表的任何一格——那张表只收「两指分工」，等于制表时就已经把它排除了。
2. **另外两个表外码元比我原先预想的轻微**：`E` = `ev`/`im`、`W` = `vw`/`mo` 确实跨掉了中排（偏离表里 7 种合法形态），但两套难度模型都算不出它们比多数合法格更差（详见 §2.3）。所以它们列**可选**，不是必改。
3. **真正的系统性问题是「权重与舒适度错配」**：31.4% 的双键码元击打权重压在「含小指」的格上（14 个码元，其中 6 个权重 ≥1.40%），而 12 个空闲格里**最舒服的 6 个全是食指格**。用你表里 13 个 `!系数` 反推出的模型显示：**「小指是否参与」是难度第一主因（+0.357），而「跨几根手指」几乎不影响（−0.002/指）**。
4. 给你 4 个方案（1 / 6 / 7 / 8 处改动）。**推荐方案 D（7 处）**：一步解决 `de/ik`、把 5 个高频码元挪出小指格、顺手把三键 `Q` 降成双键，加权难度降 2.8%（结构模型）/ 4.8%（系数反推模型），只需重学 7 个码元。
5. 改任何码元都会破坏「与空明码键位兼容」这个卖点。若这是主要顾虑，用**变体 β：加别名不删旧键位**，兼容性 100% 保留。（§4.5）

## 2. 两套难度模型

### 2.1 模型 A：结构启发式（自建，参数可调）

```
单键代价 = 手指系数 × 行系数
  手指：小 1.50 / 无 1.20 / 中 1.00 / 食外 0.85 / 食内 0.90
  行  ：上 1.08 / 中 1.00 / 下 1.15
双键代价 = 两键代价和
         + 0.10 × (指距−1)^1.6        ← 跨指宽度
         + 0.35（两键相邻排） / +0.90（两键跨两排）
         + 0.25（同指横压） / +1.20（同指纵压）
         + 0.30（三键）
难度指数 = 代价 / 代价(a+s)，即以「小指中排 + 无名中排」为 1.00
```

这套模型**偏好窄跨度**，把「小指+食指」这种 4 指宽的组合判得偏贵。改脚本顶部 `W_FINGER / W_ROW / K_*` 六个常量即可做敏感性分析。

### 2.2 模型 B：由你表里 13 个 `!系数` 反推

13 个格子带了数字（`qs` `wa` `ax` `sz` `zx` `qe` `qd` `ea` `ac` `dz` `zc` `zb` `sc`）。以「数字 = 该格难度系数」为假设做最小二乘拟合，**R² = 0.670**：

| 特征 | 系数 | 解读 |
| :--- | ---: | :--- |
| 常数 | +0.8275 | 最舒适格的基准 |
| **小指参与** | **+0.3570** | **难度第一主因**，一项抵 2.7 级行差 |
| 无名指参与 | +0.0325 | 几乎可忽略 |
| 相邻指间隔（跨几根手指） | −0.0015 | **可视为 0：跨度本身不贵** |
| 行差 | +0.1300 / 排 | 每跨一排加 0.13 |
| 两键都在上排 | +0.1320 | 上排整体偏累 |
| 上排键数 | −0.0475 / 键 | 与上一条部分抵消 |
| 两键都在下排 | 0.0000 | 不额外罚（可能是被小指项吸收） |

拟合残差最大 ±0.125（`qd`），最小 0.000（`qe` / `zb` / `sc`）。这不是唯一解（13 点拟 9 参，自由度偏低），但方向证据强：`sz`（小下+无中，1.46）与 `wa`（小中+无上，1.35）被你标为难，二者唯一共同点是**含小指**；而 `zb`（小下+食内下，跨 4 指）只有 1.18 —— 若跨度真贵，它不该这么低。

### 2.3 两模型的一致与分歧

| 判断 | 模型 A | 模型 B | 处理 |
| :--- | :--- | :--- | :--- |
| `de`/`ik` 最糟 | ✅ 表外最高 1.344 | ⚠️ 模型外（同指无法表达，需外挂罚项） | **必改**，两模型都不辩护 |
| 小指组合偏贵 | ✅（1.50 系数） | ✅（+0.357，最大项） | **共识，据此优化** |
| 宽跨度（4 指）贵 | ✅（+0.60） | ❌（≈0） | 分歧 → 不把「减跨度」当主要目标 |
| 跨两排（`E`/`W`）很糟 | ⚠️ 仅 1.095 / 1.212 | ⚠️ 1.040 / 1.071（13 个样本行差都 ≤1，纯外推） | **都不突出 → 列为可选** |
| 三键 `Q` 很糟 | ✅ 1.437（全表最高） | ⚠️ 1.241（三键罚项也是外挂） | 可选，见方案 D |

### 2.4 外部旁证（一手文献）

- **手指奴役（finger enslaving）**：相邻手指的独立性受肌腱联结与运动皮层表征重叠限制，其中**中指—无名指—小指的耦合最强，食指几乎可独立运动**（Zatsiorsky et al. 1998；见综述 *Chord skill: learning optimized hand postures and bimanual coordination*, Exp Brain Res 2023, [doi:10.1007/s00221-023-06629-2](https://link.springer.com/article/10.1007/s00221-023-06629-2)）。直接支撑「小指参与＝贵、食指可多担」。
- **和弦编码的是手部姿态**：同上综述指出，熟练后和弦以「手部姿态表征」而非单指位移编码 —— 所以「跨几根手指」不构成独立成本，与模型 B 的结论吻合；也解释了为什么「同指压条」是另一类问题（那是单指的内部自由度限制，不是姿态问题）。
- **记忆成本取决于映射的语义性**：Copher 1984 的实验中，有语义映射（字母外形→键位）的编码组 7 分钟学会，随机映射组需 50 分钟（转引自[和弦键盘及其工效学研究](http://ir.psych.ac.cn/bitstream/311026/9473/2/)）。**这是「全量重排不划算」的核心依据。**

| 指标 | 数值 |
| :--- | ---: |
| 词库条目 | 114,515 |
| 单键码元（15 个）承担击打权重 | 37.1% |
| 多键码元（44 双键 + 1 三键）承担击打权重 | 62.9% |

**含义**：空明拳的分配已经吃掉了七成优化空间，满打满算只剩 6~7%，而拿满要重学 44 个码元。收益集中在少数位置：

## 4. 候选方案（供选择）

四个方案的新键位都逐一用 librime 的 `纯形统一心法 → 指法` 规则管道模拟验证：**左手、右手镜像都能打出目标码元，与既有 121 条规则零冲突**（脚本输出见 §6）。

### 方案 A：最小手术（1 处）

| 码元 | 权重 | 现键位 | 新键位 | 右手镜像 | 模型 A | 模型 B |
| :---: | ---: | :--- | :--- | :--- | ---: | ---: |
| `>` | 0.81% | `de` | **`td`** | `yk` | 1.344 → 0.897 | 1.810 → 0.908 |

- **ΔΣ：模型 A −0.6%，模型 B −1.1%**（该码元自身难度降 33% / 50%）。
- 记忆成本：1 个码元。风险：最低。
- 适合：只想止住「`de` 按不出来」这一处痛点，不想动任何其他键位。

### 方案 B：小指减压（6 处）

`>` 拿最佳空闲格，其余 5 个「无小指」空闲格给 5 个最重的小指码元：

| 码元 | 权重 | 现键位（现格） | 新键位（新格） | 右手 | 模型 A | 模型 B |
| :---: | ---: | :--- | :--- | :--- | ---: | ---: |
| `>` | 0.81% | `de`（表外·同指） | **`td`**（中+食内/中→上） | `yk` | 1.344 → 0.897 | 1.810 → 0.908 |
| `T` | 2.05% | `qt`（小+食内/同上） | **`ts`**（无+食内/中→上） | `yl` | 1.175 → 1.046 | 1.217 → 0.940 |
| `p` | 1.86% | `qr`（小+食外/同上） | **`db`**（中+食内/中→下） | `kn` | 1.052 → 0.920 | 1.218 → 0.956 |
| `Z` | 1.62% | `fz`（小+食外/下→中） | **`gc`**（中+食内/下→中） | `h,` | 1.196 → 0.926 | 1.312 → 0.956 |
| `H` | 1.47% | `ar`（小+食外/中→上） | **`sb`**（无+食内/中→下） | `ln` | 1.137 → 1.070 | 1.264 → 0.987 |
| `B` | 1.42% | `qw`（小+无/同上） | **`gx`**（无+食内/下→中） | `h.` | 1.080 → 1.086 | 1.254 → 0.987 |

- **ΔΣ：模型 A −2.2%，模型 B −4.8%**。
- 记忆成本：6 个码元（全是双键码元，15 个单键一简完全不动 → 对一简字/词零影响）。
- 副作用：食指内列 `t/g/b` 的码元数由 6 增至 11 —— 符合「食指最强、可多担」，但会略增食指负担。`B` 换到 `gx` 在模型 A 下几乎无损（+0.006），模型 B 下明显改善。
- 若不想动 `B`，可把 `gx` 让给 `V`（1.40%）或 `A`（1.38%），`B` 留原处。

### 方案 C：B + 治跨两排（8 处，**不建议**）

在 B 之上再安置 `E`、`W`：

| 码元 | 权重 | 现键位 | 新键位 | 右手 | 模型 A | 模型 B |
| :---: | ---: | :--- | :--- | :--- | ---: | ---: |
| `E` | 1.33% | `ev` | `ea`（小+中/中→上） | `i;` | 1.095 → 1.122 | 1.040 → 1.265 |
| `W` | 1.09% | `vw` | `dz`（小+中/下→中） | `k/` | 1.212 → 1.176 | 1.071 → 1.313 |

- **ΔΣ：模型 A −2.3%，模型 B −4.0%** —— 比方案 B **更差**（模型 B 回头，模型 A 只多 0.1 个百分点）。
- 原因：这两格的替代品都含小指，换过去等于「修一个不痛的地方，占掉一个宝贵的食指格」。
- **结论：把 `E`/`W` 留在原处。** 除非你认为「跨两排」的物理别扭程度远超模型所能量化（这属于模型边界，我保留你的判断权）。

### 方案 D：B + 把三键 `Q` 降成双键（7 处，**综合最优**）

`Q` 现在是全文唯一的三键 `esf`（三指同按），模型 A 判它 1.437 —— **45 个多键码元里最贵的一个**。`ea` 是含小指空闲格里最舒服的一个，正好空着：

| 码元 | 权重 | 现键位 | 新键位 | 右手 | 模型 A | 模型 B |
| :---: | ---: | :--- | :--- | :--- | ---: | ---: |
| `Q` | 1.12% | `esf`（三键） | **`ea`**（小+中/中→上，两键） | `i;` | 1.437 → 1.122 | 1.241 → 1.265 |

- **ΔΣ（在方案 B 之上）：模型 A −2.8%，模型 B −4.8%（与 B 持平）**。即结构模型下多降 0.6 个百分点，系数模型下几乎不变；但**少了一个三键并击**，副作用是正的。
- 记忆成本：7 个码元。
- 风险点：`Q` 作为「特殊键」有一定记忆辨识度，改掉后需重新适应。

### 方案 E：全量重排（44 处，仅作参照）

按权重顺序对号入座到 53 个合法格。**ΔΣ：模型 A −6.4%，模型 B −6.9%**，需改 44/45 个键位。

**不推荐**：相比方案 D 的 −2.8%，多改 37 个码元只换 3.6 个百分点。按 Copher 1984 的实验（随机映射学 50 分钟 vs 语义映射 7 分钟）推算，这笔记忆投入换不回等价收益。

### 4.5 变体 β：加别名，而不是替换（可与任一方案叠加）

`chord_composer` 的 `xform` 允许**一个码元对应多个键位组合**。删旧规则是「替换」，保留旧规则再加一条是「别名」：

```yaml
# 替换（方案 A/B/D 的做法）：删掉 xform|de|>| 与 xform|ed|>|，改为
    - xform|td|>|
    - xform|dt|>|
# 别名（变体 β）：原有 45 条一条不动，只追加
    - xform|td|>|
    - xform|dt|>|
```

| | 替换 | 别名（β） |
| :--- | :--- | :--- |
| 旧键位 | 失效 | 仍可用 |
| 与空明码的键位兼容 | 破坏（仅被改动的码元） | **完全保留** |
| 键位总数 | 60 | 60 + 改动数 |
| 风险 | 需重建肌肉记忆，过渡期变慢 | 零风险，可先试用再决定是否删旧键位 |
| 缺点 | — | 难按的旧键位仍可能被误按；「一码元两键」需在文档标注 |

> β 是**过渡手段**：先加别名跑一两周，手感确认后，再把旧规则删掉转成正式替换。

## 7. 未确认项与风险

1. **表内 `!系数` 的确切含义我未能确证。** 我按「该格难度系数」处理，并用 13 个点反推出 R²=0.67、系数可解释的线性模型 —— 这只能说明「与数据自洽」，不等于「证明它就是难度」。若它其实是别的指标（例如某次重排评审的中间产物、或码元使用占比），**模型 B 的结论需重算，模型 A 的结论不受影响**（A 不依赖这些数字）。请告知出处，我按其口径重跑。
2. **模型 A 的参数由我设定。** 若你不认同（例如认为下排应罚得更重），改 `W_FINGER / W_ROW / K_*` 六个常量即可重跑；§2.3 已标注哪些结论是两模型共识（小指项、同指压条），哪些是分歧（跨度、跨两排）。
3. **`E`/`W` 的「跨两排」代价是纯外推。** 你给的 13 个样本行差都 ≤1；模型 B 只能线性外推。物理判断（手型被撕裂）与数据判断（不算贵）冲突，所以我把它做成方案 C 并明确标注「不划算」，把最终判断权留给你。
4. **破坏与空明码的键位兼容。** 空明拳的价值本来就是「照搬空明码键位」。若这是主要顾虑，选变体 β，兼容性 100% 保留。
5. **标点侧的压条（`fv` `dc` `fb`）未处理。** 它们的结构与原来的 `de` 同类（同指纵压 / 同指斜跨），但标点没有词库频次可比，本方案不敢动。若要一并优化，需要先给标点估一个使用权重（或按「每千字标点数」估），我可以补做。
6. **权重口径的假设。** 我按「一简/二简条目带权重、全码条目权重 0」累计码元击打次数（与该词库的写法一致：`的  _d  92123018` 与 `的  d.O  0`）。若实际 FSM 在某些路径上走了全码，权重分布会有偏移，但不会改变排序的量级。
