# 串击版 LyraIME 键盘布局（issue #57）

产物：`rime/lyraime/themes/yoyo-pure-cj.lua` —— **单个 Lua 主题文件，不改客户端源码**。
对齐校验：`python3 rime/scripts/test_cj_theme.py`。

## 1. 为什么键盘配置需要自动校验

`speller.alphabet`（Rime 侧）与键盘主题（外壳侧）是两份独立数据。错一位不会报错，
只会静默打出另一个字——而且错得合理：在串击方案里 `K` 与 `k` 是两个不同码位，
落到小写位照样出候选，只是出的是别的字。

所以校验不是「看起来对不对」，而是双向严格对账：

1. 在桩 DSL 里**真执行**主题 Lua（`rime/scripts/dump_cj_theme.lua`），拿到每个按键
   `click` / `swipe_up` / `long_click` 的解析结果（命中 `preset_keys` 就取 `text`/`commit`，
   否则当作字面键名）——这是引擎真正会读到的东西，不是文本长得像什么。
2. 与 `cj_keymap.lua` 的 60 条 `<码元, 键, 层>` 逐条比对，双向都查：缺一条、多一条都失败。
3. 校验有效性做过变异检查：把数字键 `1` 的码元从 `H` 改成 `F`，测试报出
   「`('1','digit')` 期望 `H` 实际 `F`」并连带三条覆盖断言失败。

## 2. 七行布局

```
┌──────────────────────────────────────────────────────────┐
│ 的 是 了 在 和 我 有 不 一 就 中 人        ← 快捷字条 12 格 │
├──────────────────────────────────────────────────────────┤
│ H  F  X  S  T  R  Y  Z  U  C            ← 数字行（长按出数字）│
│ ¹  ²  ³  ⁴  ⁵  ⁶  ⁷  ⁸  ⁹  ⁰                              │
├──────────────────────────────────────────────────────────┤
│ q  w  e  r  t  y  u  i  o  p                                │
│ Q  W  E        I  O  P          ← 小字为「上滑出的大写码元」│
├──────────────────────────────────────────────────────────┤
│  a  s  d  f  g  h  j  k  l                                  │
│  A     D     G     J  K  L                                  │
├──────────────────────────────────────────────────────────┤
│ z  x  c  v  b  n  m  ⌫                                      │
│        V  B  N  M                                           │
├──────────────────────────────────────────────────────────┤
│ ,  .  /  :  ;  <  >  ?                    ← 8 个符号码元    │
├──────────────────────────────────────────────────────────┤
│ 中/En        空格        '        ↵         ← ' 为次选直出  │
└──────────────────────────────────────────────────────────┘
```

## 3. 三档落位的依据

| 层 | 码元数 | 内容 | 为什么这样放 |
|---|---|---|---|
| 字母键点击 | 26 | 小写码元 `a`–`z` | 与码元同名，编码记忆零转换 |
| 数字键点击 | 10 | `T R S Y X Z F U H C` | 非小写码元里频次最高的 10 个，占独立键位 |
| 符号键点击 | 8 | `, . / : ; < > ?` | 符号本身就是码元，只能放在符号键 |
| 字母键上滑 | 16 | `A B D E G I J K L M N O P Q V W` | 剩余大写码元，复用同名小写键 |

数字键按频次分配（映射数据 `digit` 层）：`5`→T、`6`→R、`4`→S、`7`→Y、`3`→X、
`8`→Z、`2`→F、`9`→U、`1`→H、`0`→C。**长按仍出数字**，所以数字没有丢失。

## 4. 两个必须记住的实现细节

**其一，大写码元走 `text`，不走 `Shift+字母`。** librime 的 `KeyEvent` 只看 keycode，
不看 shift 位；`Shift+k` 送进去仍是小写 `k`。实测见
[`2026-10-26-cj-keyboard-delivery.md`](2026-10-26-cj-keyboard-delivery.md)。
主题里 26 个大写码元各注册一个 `preset_keys` 条目，`text = "K"` 之类，
走 `onText → simulateKeySequence` 这条已验证可用的通路。

**其二，快捷字条用 `commit`，不用 `text`。** 字条本来就绕开编码层，`commit = "的"`
直接上屏最干净；用 `text = "的"` 反而会被当作非 ASCII 字符走 `commitComposition`，
路径更绕且不易解释。

## 5. 装机与切换

1. 主题文件放到 `<LyraIME 用户数据目录>/themes/yoyo-pure-cj.lua`。
   默认用户数据目录是 `/sdcard/Documents/LyraIME`（`AppPrefs.kt:486`），
   `themes/` 是 `userThemesDir`（`DataManager.kt:63`），跨方案包共用；
   LyraIME 从该目录扫描 `*.lua`，文件名去 `.lua` 即主题 id。
2. 应用内 → 主题 → 选「麓鸣·纯形·串击」。
3. 方案仍是 Rime 侧的事：`yoyo-pure-cj` 与 `yoyo-pure-km` 同目录并存，
   在方案选单里切换（见 [`cj-deploy.md`](cj-deploy.md)）。

主题与方案是**两层独立**的：换主题不影响码表，换方案不影响键位。这个分离是有意的——
同一副键盘可以配任意 Rime 方案，但只有 `yoyo-pure-cj` 的 alphabet 与这套键位对齐。

## 6. 真机待确认（不冒充已验证）

本地只能验到「配置解析出来的键位映射正确」，以下必须真机确认：

1. **`swipe_up` 判定阈值**：会不会把「点击」误判为「上滑」，一次触摸送出两个码元。
2. **上滑与滑动光标冲突**：Trime 的空格键默认 `slide_cursor`，字母键尚未见冲突，但未实测。
3. **`postKeyJob` 单线程队列是否保序**：串击对顺序极度敏感（顺序错 = 码错），这是最大风险项。
4. **38 个 `preset_keys`（26 大写 + 12 字条）是否影响键盘加载耗时**。
5. **`'` 键能否送达**：它走 `KeyCode.parse("'")`，本地未验证该 KeyName 是否被
   `charToCode` 识别；若无响应，改用 `text = "'"` 或 `send = "apostrophe"`。
