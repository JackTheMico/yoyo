# 反查候选注释：补齐第二根（实施设计）

- 日期：2026-10-28
- 状态：**已实施**（2026-10-27 收尾；与设计的偏差见 §9）
- 前置：`docs/research/2026-10-27-反查候选注释加字根拆分.md`（可行性与现状落地）
- 决策依据：`docs/adr/0001-zigen-alignment-trust-via-code-self-consistency.md`、`docs/adr/0002-huma-pipeline-analysis-only.md`

## 1. 目标与非目标

**目标**：让三码单字的第 2 码也有字根归属。注释由

```
d.O 白d·丶O        （现状：10 字符，第 2 码无归属）
```

变为

```
白d·勺.·丶O         （新：8 字符，三码逐位对齐）
```

**非目标**（本轮明确不做）：重算码表；给词做拆分（四字词会拼出四组根+码）；改反查的匹配与排序逻辑；改 `elements.txt`。

## 2. 验收线

| 指标 | 门槛 | 怎么量 |
|---|---:|---|
| 自洽率 | ≥ 95% | 拆分能由取码规则重现已发布全码的字 / 有拆分数据的字 |
| 漂移率 | ≤ 5% | 新首/末根与旧 `elements.txt` 不一致的字 / 两者都有的字 |
| 回归 | 全绿 | `test_reverse_zigen.lua` 含真实样例断言；`test_brief_words.lua` 不受影响 |

漂移率是**体检指标而非闸门**：超过 5% 说明 0.4 与 0.2 分歧过大，停下来重估信任口径，而不是继续灌数据。

fcitx5 里的真实观感不是闸门——注释已比现状更窄（8 vs 10 字符），且 `no_zigen` 开关允许你随时退回纯码，不需要重新部署数据。

## 3. 缺口与关键数据

| 事实 | 数值 | 来源 |
|---|---:|---|
| `elements.txt` 每字导出的根数 | 首根 + 末根，共 2 | `data/elements.txt` 逐行结构 |
| 第 2 码无归属的三码字 | 4364 / 6409 = 65.8% | 上一轮探针 |
| 第 2 码对应的大码下候选主字根数 | 中位 9，平均 8.9，最少 3 | `research/probe_second_root.py` |
| 上游规范版本 | 0.4（本仓配置为 0.2） | `examples/huma.yaml` vs `zigen_table/yoyo-chai.yaml` |
| `analysis` 段结构差异 | 无，四件套一致 | 同上 |

第二根不可推断：中位 9 个候选意味着硬猜的错率约 89%。这是本设计必须引入 huma 的唯一原因。

## 4. 管线

三段，前段产物入库，后段可反复重跑。

```
                     ┌─ 一次性，离线，GPL 依赖 ─┐
zigen_table/yoyo-chai.yaml ─┐
                            ├→ export_decomposition.mjs → zigen_table/decomposition.tsv（入库）
hanzi-chai@0.4 + 字库 ──────┘                                      │
                                                                   ↓
                            zigen_table/mapping.yaml ──┐   gen_zigen_align.py
                            rime/yoyo-pure.dict.yaml ──┴→ rime/lua/yoyo/data/zigen_align.lua
                                                                   ↓
                                              reverse_lookup.lua（只改格式说明与开关）
```

### 4.1 段一：huma 导出

**新增 `zigen_table/yoyo-analysis-0.4.yaml`**：只从 `yoyo-chai.yaml` 抄 `analysis`（`classifier` / `degenerator` / `selector` / `customize`）与 `data.character_set`，`form` / `encoder` / `optimization` / `diagram` 全部丢弃。见 ADR-0002。

**新增 `zigen_table/export_decomposition.mjs`**：

- 依赖：`npm i hanzi-chai@0.4`（Node ≥ 20）。字库经上游 `fetch` 脚本取得，需联网一次。
- 对字符集内每个字调用分析，得到拆分序列，逐字写一行。
- 失败（该字分析不出）写 `status=miss`，不中断整批。

**新增 `zigen_table/decomposition.tsv`**（入库，约 100 KB，3 列）：

```
# 字<TAB>根序列<TAB>状态
的	白 勺 丶	ok
寒	宀 冫	ok
鹿	鹿	ok
```

状态取值 `ok` / `miss`。私用区字根照原样写入（TSV 是 UTF-8 明文），显示名的转换留到段二。

> 入库理由：格式调整（如上一轮把全码前缀去掉）以后还会发生，而 huma 那条链要联网、要第三方版本、要 GPL 依赖。存下来就把「改格式」和「重跑上游」解耦。

### 4.2 段二：生成注释串

改 `rime/scripts/gen_zigen_align.py`：

- 输入换成 `decomposition.tsv`；`elements.txt` 降级为**漂移体检的对照物**，不再参与生成。
- 保留现有的字根码反推投票（`derive_letters`）。`mapping.yaml` 只在反推无票时兜底——它 22 个字根的小码已与实际编码脱节（`辶` 记 `pz`、实际取 `c`），但因为自洽闸会否掉错误值，兜底是安全的。
- 渲染规则收敛成一条——**把全码逐字母分配给字根，同根的连续字母并成一组，每组写成「根 + 其字母」，组间用 `·` 连接**：

  ```
  鹿Al    → 鹿:(A,l)              → 鹿Al
  禾x·口bk → 禾:(x) 口:(b,k)      → 禾x·口bk
  白d·勺.·丶O → 白:(d) 勺:(.) 丶:(O) → 白d·勺.·丶O
  ```

  可行的分配方式只有取码规则规定的三种，逐一试：

  | 拆分序列长度 | 分配 | 例 |
  |---|---|---|
  | 1 | `r1 → (大码, 小码)` | `鹿Al` |
  | 2 | `r1 → (大码)`, `r2 → (大码, 小码)` | `禾x·口bk` |
  | ≥ 3 | `r1 → (大码)`, `r2 → (大码)`, `r末 → (大码)` | `白d·勺.·丶O` |

- **全有或全无**：分配必须覆盖全码的每一个字母，否则整字不写表项（降级为纯全码）。这条是硬约束——部分归属时若照渲染，会静默吞掉没归属的字母，把 `Al` 写成 `鹿A`，比不写更糟。

- 输出仍是 `rime/lua/yoyo/data/zigen_align.lua`，值改为**不含全码前缀**的注释串。Lua 侧因此不需要重构，只是数据变短变准。
- 必须打印：自洽率、漂移率、各形态字数、未知字根清单（新出现且 `mapping.yaml` 里没有的根——这些字必然降级，要显式报出来而不是悄悄吞掉）。

### 4.3 段三：Lua 与 schema

**`rime/lua/yoyo/reverse_lookup.lua`**：

- 删掉 `local SHOW_ZIGEN = true`。
- `make_comment` 前加开关判断：
  ```lua
  --- 开关语义取反：名为 no_zigen。未声明该开关的方案，get_option 返回 false/nil
  --- 都会被当作「未开启 no_zigen」，于是默认显示拆分；这样新增方案不必记得补声明。
  local function hint_enabled(env)
    return not (env and env.engine and env.engine.context
                and env.engine.context:get_option("no_zigen"))
  end
  ```
- 顶部注释的注释形态说明改为 `白d·勺.·丶O`。

> 取反命名的理由：无法从源码断定 `get_option` 对未声明开关返回 `nil` 还是 `false`，而两种语义下 `no_zigen` 都默认「未开启」→ 默认显示。正向名 `zigen_hint` 在其中一种语义下会把所有未声明方案的拆分静默关掉。

**schema（3 个文件各 3 行）**：`- name: no_zigen` / `states: [ 显示字根, 纯码 ]` / `reset: 0`

- `yoyo.yaml`（基础，覆盖 bm / yx / user / practice / wx 等 `__include: yoyo:/` 的方案）
- `yoyo-pure.schema.yaml`、`yoyo-pure-km.schema.yaml`（这两个在 `__patch` 里整表重写了 `switches:`，不继承基础）

## 5. 验证

1. **数据层**：`python3 gen_zigen_align.py --dry-run` 打印自洽率、漂移率、形态分布、未知字根。自洽率 < 95% 或漂移率 > 5% 时停止。
2. **Lua 层**：扩充 `rime/scripts/test_reverse_zigen.lua`，把断言换成真实样例（`的 → 白d·勺.·丶O`、`鹿 → 鹿Al`、`和 → 禾x·口bk`、以及一个降级字的纯全码），并加一条「开关开启时返回纯全码」的断言（stub 一个 `get_option` 返回 true 的 env）。
3. **回归**：`test_brief_words.lua`、`test_space_chord_brief.lua` 保持通过。
4. **手动**：`bash rime/scripts/deploy_to_fcitx5.sh` 后反查输入 `` `de ``，看候选条宽度与拆分正确性。部署脚本是整目录 `rsync lua/`，新数据文件自动带上，无需改动。

## 7. 风险登记

| 风险 | 判断 | 应对 |
|---|---|---|
| 0.2→0.4 迁移导致 `analysis` 键名不兼容 | 中 | 结构已比对一致；不兼容则改 `yoyo-analysis-0.4.yaml`，不动 `yoyo-chai.yaml` |
| 上游字库 fetch 失败或体积过大 | 中 | 一次性操作，失败则记入文档后停下，不引入半成品数据 |
| 新根不在 `mapping.yaml`，无法验证 | 低 | 必然降级；生成器显式列出，作为覆盖率缺口的说明 |
| 注释变宽 | 低 | 已从 10 降到 8 字符；且留了运行时开关 |
| GPL-3.0 传染性 | 低 | 只存 huma 的输出数据、不链接其代码；仓库已有 `elements.txt` 先例 |

## 8. 工作分解

1. 建 `zigen_table/yoyo-analysis-0.4.yaml`（从 `yoyo-chai.yaml` 抽 `analysis` + `data.character_set`）。
2. 搭 Node 环境，`npm i hanzi-chai@0.4`，跑通单字分析，确认能取到完整拆分序列。
3. 写 `export_decomposition.mjs` → `decomposition.tsv`，跑全字符集。
4. 改 `gen_zigen_align.py`：读 TSV、按形态分支渲染、打印自洽率/漂移率/未知根；`--dry-run` 先看数字。
5. 自洽率达标后再写 `zigen_align.lua`。
6. 改 `reverse_lookup.lua`（删常量、加 `no_zigen` 判断、更新注释说明）。
7. 三个 schema 加 `no_zigen` 开关。
8. 改测试并全量回归。
9. 复跑 `deploy_to_fcitx5.sh`，反查目测，按观感决定默认开还是关。
10. 更新 `README.md` 反查一节与 `docs/research/2026-10-27-*.md` 的「待办」。

## 9. 实施结论与偏差

第 1–8 步、第 10 步已落地。第 9 步的**人工目测部分未做**——沙箱无显示环境，留待 #64 收尾；数据与代码部分已达标。

### 9.1 实测结果

| 指标 | 设计门槛 | 实测 | 结论 |
|---|---:|---:|---|
| 自洽率 | ≥ 95% | **99.2%** | 过 |
| 漂移率 | ≤ 5% | **3.4%**（227 / 6640） | 过 |
| 有拆分 / 全字符集 | — | **6590 / 6640** | 50 字降级 |
| 单字注释宽度 | 8 字符 | 8 字符（`白d·勺.·丶O`） | 符合 |
| 形态分布 | — | ≥3 根 4367、2 根 1983、1 根 240 | 符合设计三分支 |

产物：`zigen_table/decomposition.tsv`（6640 行 / 119 KB）、`rime/lua/yoyo/data/zigen_align.lua`（6590 条 / 194 KB）。

降级的 50 字有共同特征：**码表把它们当双根字**（首根大码 + 末根双码），而拆分器给出三根以上。多出来的中间根（氵、亠、亍、山/一/几 一类）在码表里被并进了首根或末根。可验证的三例：

| 字 | 全码 | 码表根 | 拆分器根 |
|---|---|---|---|
| 范 | `/Yj` | 艹 + 㔾 | 艹 / 氵 / 㔾 |
| 哀 | `?bk` | 衣 + 口 | 亠 / 口 / 衣 |
| 衍 | `gns` | 彳 + 氵 | 彳 / 氵 / 亍 |

根数不一致时逐位分配无从成立，按 §4.2 的「全有或全无」整字退回纯编码，符合设计预期。完整 50 字清单由生成器打印，重跑可见。

### 9.2 与设计的偏差

**① `form` 段不能全丢——必须展开 `grouping`（影响最大的一条）**

§4.1 说 `form` / `encoder` / `optimization` / `diagram` 全部丢弃、只抄 `analysis`。实测不成立：分析器只认 `form.mapping` 的键，而 `yoyo-chai.yaml` 把从属字根（ChaiPUA 私用区字符）写在 `form.grouping` 里，只抄 `analysis` 会让这些部件认不出主根，自洽率只有 **50%**。修正做法是 `make_analysis_config.py` 把 `grouping` 的从属字根**展开进 `form.mapping`**（277 → 539 个根），自洽率升到 99.2%。丢掉的仍然只是 `encoder` / `optimization` / `diagram` / `alphabet` / `mapping_type`。

**② 字根码改为直接读表，不再反推**

§4.2 说保留 `derive_letters` 反推投票、`mapping.yaml` 兜底。实际改为**直接读 `form.mapping` 的值**，`mapping.yaml` 只用来取私用区根的中文名。理由：反推投票在多个根共享同一大码时会把票投给错误的根且不告警；直接读表后，「全有或全无」的校验变成「派生字母拼接 == 已发布全码」的显式比对，错了由自洽闸拦下，不会静默出错。`form.mapping` 与 `mapping.yaml` 确有 7 处不一致（乛/乙、彡、疋、屮、疒、辶 等），实测均为 `form.mapping` 与已发布编码一致。

**③ 上游包版本是 0.3.1，不是 0.4**

§4.1 / §8 写 `npm i hanzi-chai@0.4`。npm 上可安装的最新版本是 **0.3.1**，0.4 是上游**配置规范**的版本号（`examples/huma.yaml`），不是包版本号。0.3.1 自带字库数据（`dist/data/`），**离线可用**，因此 §4.1「需联网一次」和 §7「字库 fetch 失败」这条风险都不成立。

**④ 漂移闸落成独立退出码，消解了设计内部的矛盾**

§2 说漂移率「是体检指标而非闸门」，§5 又说「漂移率 > 5% 时停止」——两处冲突。实施取**两者都拒绝写文件、但退出码不同**的方案：自洽率不达标退出 **1**（数据不可信），漂移超线退出 **2**（分歧大、该人看一眼，但不判数据错）。这样脚本停下，而后来的人不会把两类问题混为一谈。

**⑤ 新增 `render()` 单元测试（变异检验逼出来的）**

§5.2 只要求扩充 `test_reverse_zigen.lua`。变异检验时发现：删掉「全有或全无」守卫，14 项集成测试**全部仍绿**——因为真实数据里没有触发违规的样本，守卫等于没被测到。于是新增 `rime/scripts/test_zigen_align_render.py`（11 项，其中 5 项直接打 `render()` 的守卫用例：单根字母数不符、字母数不符、首根不符、缺根、空输入）。这类守卫必须有能失败的用例，否则它就是死代码。

**⑥ 生成器的「未知字根清单」实际输出为「降级字清单」**

§4.2 要求打印「未知字根清单」。实际口径调整为打印**降级字清单**（这 50 个字就是不可对齐的全部），比按根汇总更直接可用——逐字可见才判得了是不是同类原因。

### 9.3 未完成项

- **fcitx5 真实观感**：§5.4 的人工目测未做（沙箱无显示）。注释已比现状窄（8 vs 10 字符），且 `no_zigen` 可随时退回纯码，风险低，但结论仍应由人给出。挂在 #64。
- **`no_zigen` 默认位置**：当前保持 `reset: 0`（默认显示字根）。是否改为默认纯码，取决于上一条的观感结论。
