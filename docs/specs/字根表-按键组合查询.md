## Problem Statement

音形字根表（寒梅 / 折梅）的每个码元都有一个并击按键组合（chord），共 180 个码元。用户想验证某个按键组合（如 `wt`）是否已被占用时，目前只能逐个悬停查看每个码元的指法小方阵，低效且容易漏。输入法设计者在规划新码元时也需要快速确认候选组合是否空闲。

## Solution

在音形字根表页面顶部增加一个「按键组合查询」输入框：输入 1–4 个按键（如 `wt`），页面立即告知该组合是否被占用——若占用，显示对应码元（如 `tE`，含声母 / 韵母说明与可拼音节）；若空闲，明确提示「空闲组合」。查重忽略按键顺序（并击无先后，`wt` 与 `tw` 是同一组合），与重排键位脚本的 2 键组合池语义一致。寒梅、折梅两个变体都提供该功能。

## User Stories

1. 作为音形输入法学习者，我想在字根表页面输入一个按键组合，以便快速确认它是否已被某个码元占用
2. 作为输入法设计者，我想在规划新码元时输入候选组合，以便确认它是否空闲、可以安全使用
3. 作为字根表使用者，我想输入 `wt` 这类两键组合，以便得知它对应哪个码元
4. 作为字根表使用者，我想以任意按键顺序输入（`wt` 或 `tw`），以便不用记忆并击的先后顺序
5. 作为字根表使用者，我想查询单键组合（如 `w`），以便确认 15 个单键码元（`wA` 等）的占用
6. 作为字根表使用者，我想查询三键组合（如 `dxb`），以便确认 71 个三键码元的占用
7. 作为字根表使用者，当我输入一个未被任何码元使用的组合时，我想看到明确的「空闲组合」提示，以便确认它可用于扩展
8. 作为字根表使用者，当我输入非法字符或超出本变体键位网格的键时，我想看到提示而不是报错，以便知道正确的输入方式
9. 作为字根表使用者，我想在结果中看到占用的码元标识（如 `tE`），以便定位到表格中的具体位置
10. 作为字根表使用者，我想在结果中看到该码元的声母 / 韵母说明与可拼音节，以便理解为什么是这个组合
11. 作为字根表使用者，我想在结果中看到该码元承载的字根，以便了解它的实际用途（增强项）
12. 作为字根表使用者，当输入框为空或输入全被过滤时，结果区应清空，以便页面保持干净
13. 作为寒梅使用者，我想在寒梅字根表里使用该查询，以便在 15 键网格（`qwert/asdfg/zxcvb`）范围内验证组合
14. 作为折梅使用者，我想在折梅字根表里使用该查询，以便在 20 键网格（含数字行）范围内验证组合
15. 作为使用者，我希望生成后的 HTML 自包含、无需任何服务端或外部资源即可查询，以便离线打开文件也能用
16. 作为维护者，我希望重新生成 HTML 后查询索引自动基于最新指法数据更新，以便键位重排后无需手改
17. 作为维护者，我希望生成时自动检测「同一组合被多个码元占用」的数据冲突并失败，以便错误索引绝不静默上线
18. 作为使用者，我希望查询结果醒目但不遮挡字根表，以便输入后无需滚动即可看到结果
19. 作为使用者，我希望输入框支持键盘操作（Enter 查询、Escape 清空），以便不依赖鼠标
20. 作为使用者，我希望输入大小写不敏感，以便误按 CapsLock 也不影响查询

## Implementation Decisions

- **反向索引构建（核心）**：音形字根表生成器新增一个纯函数，把指法数据（码元 → 并击组合）翻转并归一化为「组合 → 码元」映射。归一化 = 去重 + 排序（并击无顺序、同键重复无意义）。归一化后若两个码元映射到同一组合，生成时立即 assert 失败——这是本功能的**生成器内自检 seam**，保证「占用判定永远无歧义」。
- **数据内嵌**：生成 HTML 时把该变体的反向索引序列化进页面 `<script>` 常量。页面纯静态、自包含，查询在浏览器端完成，无服务端。
- **UI 位置与交互**：页面顶部（副标题下方）新增输入框与结果区。监听 `input` 事件即输即查，支持 Enter（确认）与 Escape（清空）；结果两种状态：占用（显示码元、声母 / 韵母说明、可拼音节，增强项含字根）与空闲。
- **输入校验**：只接受本变体键位网格内的键（hm：`qwert/asdfg/zxcvb`；yx：`12345/qwert/asdfg/zxcvb`），其余字符忽略；输入统一按小写处理；空输入清空结果区。韵母大写码元（`A–L`）不属于查询输入域。
- **查询语义**：整体完整匹配——输入组合作为完整 chord 参与查找（单键匹配单键码元、多键匹配多键码元）；部分子集关系不算占用（如 `w` 是 `wt` 的子集，但 `w` 命中 `wA` 而非 `tE`）。不做组合合法性判定（是否符合并击规则），只回答「是否被占用」。
- **变体共享**：yx / hm 共用同一生成器与同一段 UI 逻辑，各自嵌入自己的反向索引（键位网格不同、数据源不同）。两变体的标题、网格配置沿用现有 `VARIANTS` 表。
- **数据事实（当前 hm 状态）**：180 个码元（15 声母 × 12 韵母指法），chord 长度分布 1 / 2 / 3 键（15 / 94 / 71），全部唯一、无歧义。用户示例 `wt` 归一化后命中 `tE`（声母 t、韵母 E）。yx 变体同机制，数据来自各自的 fingering JSON。

## Testing Decisions

- **好测试的标准**：只验证外部行为——给定一个组合，页面是否报告正确的「占用（哪个码元）/ 空闲」；不测内部实现细节。
- **模块级 seam（首选，生成器内自检）**：构建反向索引的纯函数在生成时对当前数据跑一遍，断言归一化后无「一组合多码元」冲突。当前 hm / yx 数据均已验证通过（hm：180 码元 ↔ 180 唯一组合）。
- **页面级手工验证**：重新生成 yx / hm 两个 HTML 后，浏览器中逐项验证：`wt` → 显示 `tE`；`w` → 显示 `wA`；`dxb` → 显示 `bH`；一个不存在的组合（如 `jk`）→ 空闲提示；非法字符 / 超网格键 → 提示而非报错；顺序无关（`wt` 与 `tw` 结果一致）。
- **遵循项目现状**：本项目无自动化测试框架，延续「生成脚本 + 手工页面验证」的既有实践（与纯形字根表、练习工具同风格），不引入新测试栈（用户已确认该 seam）。

## Out of Scope

- 纯形字根表（zigen_table.html，60 键位一维结构）不在本功能范围。
- 组合合法性判定（该组合是否符合并击指法规则、是否在 2 键组合池内）——本功能只回答「是否被占用」。
- 键位 / 指法本身的修改，码元迁移或重排建议。
- 批量能力（如「列出全部空闲 2 键组合」）——只做单个组合查询，可作为后续迭代。
- 服务端 / 持久化 / 多用户能力——纯静态单文件。

## Further Notes

- 与键位重排脚本的关系：若未来重排寒梅 / 折梅键位，重新运行生成器即可让索引自动更新；生成器内自检可捕获重排引入的组合冲突。
- 数据来源与练习工具同源（fingering JSON 由练习工具生成脚本从 yoyo.yaml 推导）；若后续给练习工具加同类查询，可复用同一反向索引构建逻辑。
- 增强候选（本次不做）：结果中展示该码元承载的字根图片与说明（与现有字根 tooltip 复用同一数据）；输入框旁附「占用 / 空闲」统计（如已用 180 / 空闲组合数）。
