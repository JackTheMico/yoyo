# huma 管线只跑分析，不重算编码

为补齐第二根而重跑 huma 时，只把 `analysis` 与 `data` 两段迁到上游 0.4 规范，`form` / `encoder` / `optimization` 一律不运行、不输出编码。理由是：我们需要的只有拆分序列，而全码已经是既成事实——`yoyo-pure.dict.yaml` 与 `yoyo-bm.dict.yaml` 里的码是 0.2 时代产物，其中还含人工决定（`yoyo-chai.yaml` 的 `info.description` 记着「为一简字固定了一键式排布」，如 `十S → e`）。这些排布不是 `encoder` 能重新推导出来的东西，重跑优化器只会产出一份不同的码表，把「拆分能不能信」这个可验证的问题，变成「要不要换码表」这个不可验证的问题。

**Considered options**：完整迁移（连编码一起跑，可对照 0.2 拆分是否正确，但会引入码表漂移的额外争议）；锁旧版 0.2 实现（旧版是 Python 且依赖旧数据库、开发停滞，环境成本高且不保证可运行）。

**Consequences**：仓库里从此并存两套「真值」——已发布码表是编码真值，huma 输出的拆分序列是拆分真值，两者靠自洽闸（ADR-0001）互相约束。若将来真要重算编码，那是另一个决策，需另立 ADR。
