# 字根拆分的信任口径：编码自洽优先于复现历史

反查注释要显示 6435 个单字的码位对齐拆分，但 `elements.txt` 每字只导出首根与末根，缺第二根；而第二根无法从现有数据推断——按大码统计，那个位置平均对应 8.9 个候选主字根（中位数 9）。补齐只能重跑上游 huma，而上游规范已从 `yoyo-chai.yaml` 的 `version: '0.2'` 演进到 `0.4`，重导不可能逐字复现当初的拆分。因此采信标准定为**自洽**：新拆分若能由取码规则重现该字已发布的全码（首根大码 = 码 1、次根大码 = 码 2、末根大码 = 码 3），即采信；与旧 `elements.txt` 的分歧只作漂移体检，超过 5% 就停下重估，而不作为拒绝条件。

**Considered options**：严格复现（只接受与旧数据一致的结果，实质要求锁死 0.2 实现）；双重闸（自洽 + 首末根逐字一致，会白白丢掉本来正确的字）。

**Consequences**：注释可能展示一个「能被码验证、但未必是当初那一个」的中间根。由于它的大码恒等于码 2，用户照着打出的键永远是对的；风险被限制在同一大码组内，而不是错误编码。换来的是一条不依赖历史版本、可反复重跑的管线。
